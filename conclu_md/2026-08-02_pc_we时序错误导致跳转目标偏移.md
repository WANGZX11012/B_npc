# 2026-08-02 pc_we 时序错误导致跳转目标偏移

## 概述

多周期 NPC（AXI4-Lite 版）运行 `am-kernels/tests/cpu-tests/bit` 测试时卡死，无法 HIT GOOD TRAP。
根因是 [ctrl.v](vsrc/ctrl.v) 的 `pc_we` 时序错误：放在 FET 阶段导致 PC 更新用了上一条指令的译码信号，跳转目标偏移 +4。
最终修复为将 `pc_we` 移到 WB 阶段。

## 现象

### 假象一：4 inst GOOD TRAP

首次 `make run IMG=bit-riscv32-npc.bin` 立即输出：

```
npc: HIT GOOD TRAP at pc = 0x80000010, total_inst = 4
```

直觉判断"bit 测试不可能只 4 条指令"，定位为假象。

根因：[inst_mem.v](vsrc/inst_mem.v) 的 `initial` 块放了 4 条 built-in 占位指令（末尾 `ebreak`），
`$readmemh("build/img.hex")` 因文件不存在静默失败，`mem[4..]` 全为 X。
`make run` 传入的 `.bin` 只存在 `img_path` 字符串里，**根本没写进 Verilog 内存**，
所以跑的是 4 条占位指令，末尾 `ebreak` 触发 halt，被误判为测试通过。

### 假象二：生成 img.hex 后卡死

手动生成 `img.hex` 后再跑，10s/30s 超时无任何 TRAP 输出，卡死。
加上 `WAVE=y` 持续写波形文件，磁盘被写爆。

## 排查过程

### 1. 单步定位卡死点

用 sdb 单步（喂 `si` 命令），观察 PC/state：

```
pc=0x80000000 ×3  → li
pc=0x80000004 ×3  → auipc
pc=0x80000008 ×4  → addi
pc=0x8000000c ×6+ → 卡住，ir 一直是 addi，jal 取不到
```

FET 等待 `ifu_done` 的 cycle 数递增（3→4→6→卡死），非纯随机 stall。

### 2. 二分排除 LFSR/DELAY

临时关闭 `CONFIG_HAS_LFSR` 和 `CONFIG_DATA_MEM_DELAY`，卡死变为"能跑但跳转错"：

```
pc=0x8000000c ir=0x1f8000ef (jal, 目标应为 0x80000204)
pc=0x80000208 ir=0x00050463 (实际跳到 0x80000208，比正确目标 +4)
```

确认 LFSR 只是加剧问题，根因在 PC 跳转逻辑。

## 根因

[ctrl.v:50](vsrc/ctrl.v#L50) 原始代码：

```verilog
assign pc_we = ifu_done && (state == FET);
```

`pc_we` 在 **FET 完成（取指）时**更新 PC，但此时 `IR` 还是**上一条指令**（当前指令刚取到、尚未锁存译码）。
因此 [IFU.v:94](vsrc/IFU.v#L94) 的 `next_pc` 用的 `npc_sel`/`alu_result` 都是上一条指令的译码结果。

后果链：

1. 跳转指令（jal/branch/jalr）的跳转效果**滞后一条指令**才生效——在取下一条指令的 FET 时才用本条指令的 `npc_sel`。
2. 但此时 `pc_reg` 已是下一条地址（顺序 +4），`alu_result = pc_reg + imm` 比正确目标多 4。
3. 顺序指令（li/addi）因 `next_pc = pc4 = pc+4` 恰好不受影响，所以前几条能跑；一到 jal 就 PC 错乱。

## 修复

### 尝试一：pc_we 移到 EXE（引入新 bug）

将 `pc_we` 改为 `(state == EXE)`，jal 跳转目标正确了，但 `ret`（jalr）返回地址错误：

```
ret 后 pc=0x8000002c（应为 0x800000c4）
```

根因：`pc_we` 在 EXE 更新 `pc_reg` 后，WB 阶段写 `ra` 时 [IFU.v:91](vsrc/IFU.v#L91) 的 `pc4 = pc_reg + 4`
已变成**跳转目标 + 4**，而非**原 pc + 4**，导致 `ra` 写错。

### 尝试二：pc_we 移到 WB（最终修复）

[ctrl.v:50](vsrc/ctrl.v#L50) 最终：

```verilog
assign pc_we = (state == WB);
```

正确性：

- **WB 时 `pc_reg` 仍是本条指令地址** → `pc4 = pc_reg + 4` 正确写入 `ra`（jal/jalr 返回地址）。
- **WB posedge 更新 `pc_reg <= next_pc`** → 下一拍 FET 用新 PC 取指。
- `next_pc` 用的 `alu_result` 在 WB 仍正确（IR 不变、`pc_reg` 不变）。

## 验证

单步确认跳转正确：

```
0x8000000c jal → 0x80000204 (_trm_init)  正确
0x80000048 ret → 0x800000c4 (返回 main)   正确
```

完整运行（LFSR + DELAY 全开）：

```
npc: HIT GOOD TRAP at pc = 0x8000021c, total_inst = 312
```

## 附带修复：img.hex 自动生成

原 `make run` 不会生成 `img.hex`，导致 `$readmemh` 静默失败、跑占位指令。
已在 [Makefile](Makefile) 的 `run` 目标加入自动转换：

```makefile
BIN2HEX := $(NPC_HOME)/../abstract-machine/tools/bin2readmemh.py
IMG_HEX := $(BUILD_DIR)/img.hex

run: all
ifneq ($(IMG),)
	@python3 $(BIN2HEX) $(IMG) $(IMG_HEX)
endif
	@./$(BUILD_DIR)/V$(TOPNAME) -b $(RUN_FLAGS) $(IMG)
```

## 教训

1. **多周期 PC 更新时机**：`pc_we` 必须在本条指令译码+执行完成、且 `pc4` 仍正确的阶段更新，WB 是正确选择。FET 太早（用上一条信号），EXE 会破坏 `pc4`（ra 写错）。
2. **"假 GOOD TRAP"警惕**：halt 判定只看 `ebreak`，占位指令末尾 ebreak 会伪装通过。必须核对 `total_inst` 是否合理。
3. **`$readmemh` 失败静默**：文件不存在只 warning 不报错，内存为 X。镜像加载链路必须显式验证。
4. **波形会写爆磁盘**：卡死时 `WAVE=y` 持续写波形。排查死锁先关波形。
