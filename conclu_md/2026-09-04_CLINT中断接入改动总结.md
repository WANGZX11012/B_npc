# CLINT 时钟中断接入：改动与 Bug 总结（2026-09-04）

## 0. 目标与现状

- 目标：在 NPC 多周期核上打通 CLINT 时钟中断（硬件 mtip → 软件 `EVENT_IRQ_TIMER` → 重装载 → mret）。
- 结果：**已通**。
  - `am-kernels/tests/am-tests` `mainargs=i`：持续打印 `t` 并 `HIT GOOD TRAP`，`total_inst=50090702`。
  - `mainargs=h`：`total_inst=1915` 与基线完全一致（未回归）。
  - `cpu-tests`：全 PASS。

## 1. 中断通路总览（改动后的数据流）

```
        ┌─────────────────────────── core.v ───────────────────────────┐
        │                                                              │
 clint  │  mtime ──► (>=) ──► mtip ──┐                                 │
 (mtime │  mtimecmp ─────────────────┤                                 │
  ≥cmp) │                            ▼                                 │
        │              assign irq_taken  (core.v:345)                  │
        │                = ctrl_at_state_wb        // 指令边界(WB拍)    │
        │                & csr_mstatus_mie         // 软件 iset() 开   │
        │                & clint_mtip              // 硬件请求         │
        │                & npc_sel != NPC_ECALL    // 排除 ecall       │
        │                & npc_sel != NPC_MRET     // 排除 mret        │
        │                            │                                 │
        │        ┌───────────────────┴───────────────────┐             │
        │        ▼                                       ▼             │
        │  IFU.irq_taken                          CSRFile.irq_trap     │
        │  next_pc = mtvec  (IFU.v:71)            mcause=0x8000_0007   │
        │  (无视本条指令的跳转意图)                 mepc  = trap_pc      │
        │                                          MPIE<-MIE, MIE<-0   │
        └──────────────────────────────────────────────────────────────┘

  软件侧:
    mtvec = __am_asm_trap ──► trap.S 保存 Context ──► __am_irq_handle()
       └─► case 0x80000007: ev=EVENT_IRQ_TIMER; __am_timer_rearm(); ──► mret
                                                     └─ mtimecmp = mtime + INTERVAL
```

**关键点**：`mtip` 是**电平**信号（`mtime >= mtimecmp`），硬件不会自动清除。软件每次进中断必须重装载 `mtimecmp`，否则 `mret` 恢复 MIE 后立刻再次陷入，死循环。

## 2. 改动总表

| 文件 | 改动 | 为什么改 |
|---|---|---|
| [clint.v](vsrc/clint.v) | 加 `rst` 端口；`mtime`/`mtimecmp`/`aw_half`/`bvalid`/`rvalid`/`mtip_temp` 全部带复位；`mtimecmp` 初/复位值 `64'hffff_ffff_ffff_ffff`；`mtip` 打一拍输出 | 复位后必须是「永不触发」态，否则 `cte_init` 设好 mtvec 前中断就乱入；比较器毛刺用寄存器隔离 |
| [core.v](vsrc/core.v) | 声明并 assign `irq_taken` / `trap_pc`；连到 IFU、CSRFile | 中断响应必须在**指令边界**（WB 拍）判决，且要区分「中断存下一条 / 异常存自己」 |
| [CSRFile.v](vsrc/CSRFile.v) | 新增 `irq_trap` 分支：`mcause<=MCAUSE_MTIMER`、`mepc<=ecall_pc`、`MPIE<-MIE`、`MIE<-0`、`MPP<-3` | 中断进 trap 时保存现场并关中断（天然不嵌套） |
| [IFU.v](vsrc/IFU.v) | `assign next_pc = irq_taken ? csr_mtvec : npc_normal;` | 中断劫持：无视当前指令的跳转意图，强制跳 trap 入口 |
| [axi_xbar.v](vsrc/axi_xbar.v) | 新增 CLINT 从口（AR/R/AW/W/B）与译码 `ar_clint` / `aw_clint`；`mmio_sel` 纳入 clint | 让 mtimecmp 的写能真正落到 clint，且 difftest 跳过 MMIO |
| [arbiter.v](vsrc/arbiter.v) | **本轮未改动**（记录现状：单请求 + `sel_is_ifu` 归属锁存 + IFU 优先 + 一次一笔） | 中断不经过 arbiter 新逻辑，走原有 IFU/LSU 通路 |
| [timer.c](abstract-machine/am/src/riscv/npc/timer.c) | 新增 `__am_timer_rearm()`；`__am_timer_init()` 改为调用 rearm | 不 rearm 则 mtip 恒高，中断出不去 |
| [cte.c](abstract-machine/am/src/riscv/npc/cte.c) | 实现 `iset()` / `ienabled()`；`switch` 增加 `case 0x80000007` | AM 的 CTE 层要求；没有 case 会落 `default` 报 EVENT_ERROR |
| [ioe.c](abstract-machine/am/src/riscv/npc/ioe.c) | `ioe_init()` 中调用 `__am_timer_init()`（第 36 行） | AM 初始化时装载第一次闹钟，否则永不触发 |

## 3. 逐文件说明

### 3.1 [clint.v](vsrc/clint.v)

- **地址布局**（自定义，与 ysyxSoC 标准不同，见第 6 节技术债）：
  - `0xa0000050` = `mtime[31:0]`（只读）
  - `0xa0000054` = `mtime[63:32]`（只读）
  - `0xa0000058` = `mtimecmp[31:0]`（读写）
  - `0xa000005c` = `mtimecmp[63:32]`（读写）
- **`aw_half`**（[clint.v:62](vsrc/clint.v#L62)）：AW 握手是协议保证 `awaddr` 有效的最后一拍，必须在此登记「这次写哪个半区」，`aw_half = awaddr[2]`。删掉它 → 隐式 1 位线恒 0 → 高 32 位永远写不进（详见 Bug 1）。
- **复位值**（[clint.v:59](vsrc/clint.v#L59) / [clint.v:74](vsrc/clint.v#L74)）：`mtimecmp = 64'hffff_ffff_ffff_ffff`（永不触发）。`initial` 不响应复位，所以必须在 always 里显式写一遍。
- **`mtip` 打一拍**（[clint.v:121](vsrc/clint.v#L121)）：64 位比较器是组合大逻辑，`mtip_temp` 寄存一拍再输出，隔离毛刺、改善时序。

### 3.2 [core.v](vsrc/core.v)

- 判决式（[core.v:345](vsrc/core.v#L345)）：

```verilog
assign irq_taken = ctrl_at_state_wb      // 只在 WB 拍 = 指令边界, 保证原子性
                && csr_mstatus_mie       // 软件 iset() 打开才响应
                && clint_mtip            // 硬件请求
                && (idu_npc_sel != `NPC_ECALL)
                && (idu_npc_sel != `NPC_MRET);
```

- **排除 ecall / mret 的原因**（关键陷阱）：
  - `ecall`：`npc_normal` 恰好等于 `mtvec`，若此时响应中断，`mepc` 会被写成 `mtvec`，返回地址丢失。
  - `mret`：`npc_normal` 恰好等于 `mepc`，新 `mepc` = 旧 `mepc`，`mret` 后原地死循环。
- **`trap_pc`**（[core.v:352](vsrc/core.v#L352)）：`irq_taken ? ifu_npc_normal : ir_pc`
  - 中断：硬件在指令边界响应，当前指令已执行完，`mepc` 存**下一条**（软件**绝不能 +4**）。
  - 异常：存**自己**（软件 `c->mepc += 4` 跳过）。
- 命名：`irq_taken` / `trap_pc` 是 core 内部信号，**不能**加 `csr_` 前缀（`csr_` 只用于 CSRFile 的输出，见 Bug 3）。

### 3.3 [CSRFile.v](vsrc/CSRFile.v)

- 中断分支（[CSRFile.v:86](vsrc/CSRFile.v#L86)）：

```verilog
else if (irq_trap && at_state_wb)
begin
  mcause <= `MCAUSE_MTIMER;   // 32'h8000_0007: bit31=1(中断), bit[30:0]=7(机器模式定时器)
  mepc   <= ecall_pc;         // 端口名沿用, core 传入的已是 trap_pc
  mstatus[7]   <= mstatus[3]; // MPIE <- MIE   存档
  mstatus[3]   <= 1'b0;       // MIE  <- 0     关中断, 天然不嵌套
  mstatus[12:11] <= 2'b11;    // MPP  <- M-mode
end
```

- **复位值 `32'h1800`**（[CSRFile.v:58](vsrc/CSRFile.v#L58)）= `0b1_1000_0000_0000`：
  - `bit12:11 = 2'b11` → MPP = M-mode
  - `bit7 = 0` → MPIE = 0
  - **`bit3 = 0` → MIE = 0（关中断）**
  - 复位必须关中断，否则 `cte_init` 设好 `mtvec` 之前中断就会乱入（见 Bug 6）。
- **写 mstatus 的策略**（[CSRFile.v:100](vsrc/CSRFile.v#L100)）：`csrrs` 走**按位或**，`csrrw` 走**整字覆盖**。所以 `iset()` 必须用 `csrr` 读出 → C 里改 bit → `csrw` 整字写回；若用 `csrrs` 清 bit，`|0x8` 之外的清零根本无法生效（关不掉中断）。

### 3.4 [IFU.v](vsrc/IFU.v)

[IFU.v:71](vsrc/IFU.v#L71)：`assign next_pc = irq_taken ? csr_mtvec : npc_normal;`
中断优先级高于一切跳转/分支，直接劫持 PC 到 trap 入口。

### 3.5 [arbiter.v](vsrc/arbiter.v) — 本轮未改，记录现状

- 归属锁存 `sel_is_ifu`（[arbiter.v:34](vsrc/arbiter.v#L34)）：空闲时锁存这一单归谁，**IFU 固定优先**；交易期间 `sel` 不动，保证 payload 稳定。
- 响应路由（[arbiter.v:62](vsrc/arbiter.v#L62)）：`ifu_done = m_done & sel_is_ifu`，输家 `done=0` 自然阻塞；`rdata` 广播给双方无害。
- **局限（流水线的拦路虎）**：一次只处理一笔、无 outstanding。流水后 IFU 每周期取指 + LSU 并发访存，这个模块必然重写。

### 3.6 [axi_xbar.v](vsrc/axi_xbar.v)

- 读译码（[axi_xbar.v:99](vsrc/axi_xbar.v#L99)）：`ar_clint = (m_araddr[31:3] == 29'h1400000a) || (...== 29'h1400000b)` → 覆盖 `0xa0000050~0x5f`（mtime + mtimecmp）。
- 写译码（[axi_xbar.v:104](vsrc/axi_xbar.v#L104)）：`aw_clint = (m_awaddr[31:3] == 29'h1400000b)` → **只路由 mtimecmp**（`0xa0000058~5f`）；写 mtime 落默认 DECERR（只读语义）。
- `clint_wvalid` 用 `aw_clint` 而非 `awvalid` 门控（[axi_xbar.v:118](vsrc/axi_xbar.v#L118)）：AW 通道撤掉 valid 后地址译码还在，W 通道才能正确归属。
- `mmio_sel`（[axi_xbar.v:154](vsrc/axi_xbar.v#L154)）：clint 访问纳入 MMIO 标记，difftest 跳过（NEMU 侧没有 CLINT，不比）。

### 3.7 [timer.c](abstract-machine/am/src/riscv/npc/timer.c)

- `CLINT_MTIMECMP`（[timer.c:18](abstract-machine/am/src/riscv/npc/timer.c#L18)）= `CLINT_ADDR + 8` = `0xa0000058`；`TIMER_INTERVAL = 10000000u`（[timer.c:19](abstract-machine/am/src/riscv/npc/timer.c#L19)），单位 = mtime 周期数。
- **`__am_timer_rearm()`**（[timer.c:48](abstract-machine/am/src/riscv/npc/timer.c#L48)）：

```c
uint32_t lo = *(volatile uint32_t *)(CLINT_ADDR + 0);   // 读 mtime 低
uint32_t hi = *(volatile uint32_t *)(CLINT_ADDR + 4);   // 读 mtime 高
uint64_t next = (((uint64_t)hi << 32) | lo) + TIMER_INTERVAL;

*(volatile uint32_t *)(CLINT_MTIMECMP + 4) = 0xffffffffu;            // 高32位封顶
*(volatile uint32_t *)(CLINT_MTIMECMP + 0) = (uint32_t)next;         // 写低32位
*(volatile uint32_t *)(CLINT_MTIMECMP + 4) = (uint32_t)(next >> 32); // 写真高32位
```

- **三步写顺序不能变**：先把高 32 位封顶成全 1，杜绝「新低 + 旧高」的中间态误触发。
- **`__am_timer_init()`**（[timer.c:61](abstract-machine/am/src/riscv/npc/timer.c#L61)）改为直接调用 rearm，由 `ioe.c:36` 在 AM 初始化时装载第一次闹钟。

### 3.8 [cte.c](abstract-machine/am/src/riscv/npc/cte.c)

- `iset()` / `ienabled()`（[cte.c:73](abstract-machine/am/src/riscv/npc/cte.c#L73)、[cte.c:81](abstract-machine/am/src/riscv/npc/cte.c#L81)）：操作 `mstatus` 的 **bit3 = MIE**。
  - 必须用 `csrr` + `csrw`：NPC 的 IDU 只译 `csrrw` / `csrrs`，**不支持 `csrc` / `csrrci`**，所以只能用 C 做「读—改—写」（`|= 0x8u` / `&= ~0x8u`）。
- 新增 case（[cte.c:28](abstract-machine/am/src/riscv/npc/cte.c#L28)）：

```c
case 0x80000007:
  ev.event = EVENT_IRQ_TIMER;
  __am_timer_rearm();   // 往后拨闹钟
  break;                // 漏了这行会落 default, 见 Bug 5
```

- **`mepc` 处理差异**：`case 11`（ecall）里 `c->mepc += 4`；中断 case **绝不能 +4**（中断的 `mepc` 已经是下一条指令）。

### 3.9 [ioe.c](abstract-machine/am/src/riscv/npc/ioe.c)

`ioe_init()` 第 36 行调用 `__am_timer_init()`，装载首次闹钟。不调用则 `mtimecmp` 保持全 1，永不触发中断。

## 4. Bug 记录（按发现顺序，含根因）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 中断永不触发，`mtimecmp[63:32]` 恒 `0xFFFFFFFF` | `clint.v` 的 `reg aw_half` 及其 always 被删，变成**隐式 1 位线恒 0**，写永远落在低 32 位，高 32 位保持复位值全 1 → `mtime >= mtimecmp` 永不成立 | 恢复 `reg aw_half` + always（`aw_half <= awaddr[2]`，带 rst） |
| 2 | Verilator MULTIDRIVEN | `mtimecmp` 在两个 always 里都被写（一个写数据、一个在 B 通道写） | 合并为**一个** always 写 `mtimecmp`；`bvalid` 单独一个 always，只管应答 |
| 3 | `core.v` assign 用了未声明信号 + 命名违规 | `irq_taken` 没在信号声明区声明（隐式线）；且误写成 `csr_irq_taken` / `csr_trap_pc`，`csr_` 前缀专属于 CSRFile 输出 | 在 [core.v:109](vsrc/core.v#L109) 补声明；全改名为 `irq_taken` / `trap_pc`（3 处） |
| 4 | 编译报 `redefinition of __am_timer_init` | 新增 rearm 版 init 后，旧的空函数体没删 | 删除旧的空 `__am_timer_init()`，只留调用 rearm 的版本 |
| 5 | 中断确实进来了，但打印 `ev=4`（EVENT_ERROR）后 panic | `case 0x80000007` **漏了 `break;`**，落穿到 `default`，`ev.event` 被从 5 覆盖成 4 | 补 `break;` |
| 6 | 误以为复位后 MIE = 1，怀疑「中断为什么没被响应」 | 概念错：复位 `mstatus = 32'h1800`，`bit3(MIE) = 0`。**复位必须关中断**，否则 `cte_init` 设好 `mtvec` 前中断就会乱入 | 无需改码；明确复位值逐位展开（见 3.3） |
| 7 | （隐含陷阱）用 `csrrs` 关中断无效 | `CSRFile.v:100`：`csrrs` 走按位或，无法清 bit | `iset()` 强制用 `csrr` + C 改位 + `csrw` 整字写回 |

## 6. 遗留与技术债（单独记账，不挤进功能改动）

1. **CLINT 地址布局与 ysyxSoC 不一致**（最大隐患）：
   - 现在：基址 `0xa0000050`，`mtime@+0`、`mtimecmp@+8`。
   - ysyxSoC：基址 `0x0200_0000`，`mtime@0xBFF8`、`mtimecmp@0x4000`。
   - 影响面：`axi_xbar.v` 的 `ar_clint`/`aw_clint` 译码 + `timer.c` 的 `CLINT_ADDR`/`CLINT_MTIMECMP`。**接 SoC 前一次性改完，不要改两次。**
2. **mtime 计数速率**：现在是「每周期 +1」，ysyxSoC 的 CLINT 是分频后的固定频率。定了频率才能算准 `TIMER_INTERVAL`。
3. **`AXI_OVERVIEW.md` 已过期**：描述的还是 IFU/LSU 各自挂独立 `axi_lite_master` + `inst_mem`/`data_mem` 的老架构，与现在 `arbiter → master → xbar → {mem, uart, rtc, clint}` 不符，需更新。
4. **`rtc.v` 无复位**、`always @` 空格等风格项：纯技术债，与本次功能无关，单独排期。
5. **arbiter 单 outstanding**：流水线的拦路虎，见 3.5。
